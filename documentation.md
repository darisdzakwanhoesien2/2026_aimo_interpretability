## One-paragraph summary

Given a math problem and one of a fixed set of frontier reasoning models, predict
whether that model's reasoning on that problem is **robust** or **spurious**.
Operationally (reverse-engineered from the released data — §"Label definition"):
**robust = the model solves the base problem and every perturbed variant with
zero accuracy loss; spurious = at least one perturbation family causes a large
accuracy drop.** You run the named model yourself inside an offline container and
may use weights, activations, token probabilities, and generated chain-of-thought.
Output is one `bool` per (model, problem). Scored on binary accuracy.

## The interface (verified — `ingestion.py`)

`solution.py` at the ZIP root must define:

```python
def are_robust(model_id: str, problems: list[str]) -> list[bool]: ...
```

- The harness **groups cases by `model_id` and calls `are_robust` once per model** with all of that model's problem strings.
- Return: `list`, `len == len(problems)`, every element `type(x) is bool` (not `np.bool_`, not `int`), input order preserved.
- **Any exception, wrong length, or non-bool element ⇒ that model's *entire* batch is marked invalid** (all predictions `False`, `valid=False`). So `solution.py` must catch everything internally and fall back to `[False]*n`.
- Inputs the method receives: **only the problem strings**. No case IDs, no `permutation_type`, no labels, no dataset files, no network.

### `model_id` is a Codabench alias, not an HF id

The harness passes aliases like **`qwen3-8b:low`** (model + reasoning-effort
suffix). The method resolves the alias itself. Known mapping (getting-started
`config.py`): `qwen3-8b:low` → `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B`. The
`<safe-model-id>` filesystem form replaces `/ : whitespace` with `_`
(`qwen3-8b:low` → `qwen3-8b_low`). Full alias list for all 4 models: **TBD — get from Discord / a real eval run.**

## Label definition (from `examples/baselines/data/`, `math-robust-*.csv`)

Rows carry `base_accuracy`, `permuted_accuracy`, `absolute_accuracy_decay`,
`relative_accuracy_decay`, `n_detrimental_permutations`,
`permutations_causing_decay`, `model_is_robust`.

On the 141 aggregated problems:
- `model_is_robust == True` ⟺ `absolute_accuracy_decay == 0.0` exactly (n=36, `n_detrimental_permutations == 0`)
- `model_is_robust == False` ⟺ `absolute_accuracy_decay ∈ [0.5, 1.0]`, mean 0.835 (n=105)

**Class balance ≈ 25% robust / 75% spurious.** A constant-`False` predictor scores
**≈ 0.74 accuracy** on this data. This is the number to beat, not 0.5.
(The private test covers 4 models; balance may differ per model — the stronger
`gpt-oss-120b` likely has more robust cases.)

### Perturbation families (`permutation_type`)

`distract`, `rename`, `rephrase`, `typos`, `domain`. Variants generated by
`gpt-oss-120b` (`permutation_source = gpt-oss-120b-gguf_low`).
**Not provided to submissions at evaluation.**

## Tracks

| Track | Constraint | Marker | Codabench |
|---|---|---|---|
| **Main** | any model, no size limit | ZIP must **not** contain `small.txt` | task "main" |
| **Small Models** | models < 10B params | ZIP **must** contain root `small.txt` (contents ignored, case-insensitive) | task "small" |

One method may enter both (same ZIP + marker). A missing/unexpected marker fails
the submission before `solution.py` is imported. Both tracks report `accuracy`,
`coverage`, `invalid_predictions`; separate leaderboards.

## Evaluation (verified — `scoring.py`)

- `accuracy = correct / total` where `total` = **all reference labels** → invalid/uncovered predictions lower accuracy directly.
- `coverage = covered / total` — must be exactly `1.0`.
- `invalid_predictions = (total − covered) + malformed + duplicate_ids + extra_ids`.
- **Primary ranking = accuracy.** Tiebreak = mean wall-clock over 3 trials.
- Prediction run and scoring run are timed separately.

## Compute & runtime (verified — `README.md`, `Dockerfile.competition`)

- **8× NVIDIA RTX PRO 6000** (Blackwell sm_120, 96 GB each), all visible → `device_map="auto"` can shard. Shared workers → free VRAM may be < nominal.
- 192 CPU cores, no per-container memory cap.
- **3600 s per run**, applied separately to prediction and scoring. Loading the 8B model ≈ 1 min of that.
- **No network.** `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `HF_HOME=/app/data/huggingface` (read-only cache). Use `from_pretrained(..., local_files_only=True)`.
- Base image: `pytorch/pytorch:2.12.1-cuda13.2-cudnn9-runtime` (digest-pinned).
- **Preinstalled, no `pip install` at eval:** torch 2.12.1 / CUDA 13.2, transformers 5.13.0, accelerate 1.13.0, huggingface-hub 1.22.0, tokenizers 0.22.2, safetensors 0.8.0, scikit-learn 1.8.0, joblib 1.5.3, pandas 3.0.3. Anything else must be **vendored** into the ZIP; a bundled `requirements.txt` does nothing.
- Serialize sklearn/joblib artifacts with **exactly these versions**.

## Official baselines

1. **Representation probe** (`examples/baselines` + getting-started `trained-probe`) — 1 forward pass/problem, last input-token hidden state per layer, linear probe (or RBF kernel, opt. PCA) → `absolute_accuracy_decay`, repeated `StratifiedGroupKFold` (5 seeds × 4 folds, grouped by problem). Submission ships a probe *ensemble* pickle (schema v2), scores `mean(w·h + b − threshold) ≥ 0`. Uses `holmes-evaluation`.
2. **Uncertainty profiling** (getting-started `uncertainty-profiling`) — greedy decode (≤2048 prompt / ≤4096 new tok), **14 token-distribution features** (mean logprob/prob/nll, ppl, min/max/std logprob, Min-K% logprob k=0.2, entropy, top-1 prob, top-2 margin, frac selected-is-top1, frac high/low-conf), sklearn regressor (RF/ExtraTrees/HistGBR by grouped OOF balanced acc) → decay → threshold. **Checked-in artifact: grouped OOF balanced accuracy 0.626, plain accuracy 0.688, MAE 0.343** (below the 0.74 majority baseline on raw accuracy).
3. `always-true` / implicit `always-false` — trivial valid baselines.

## Local workflow

```bash
cd examples/getting-started && uv sync
uv run scripts/import_hf_dataset.py                     # needs HF_TOKEN with val-sample access
uv run scripts/run_local.py solutions/trained-probe \
  --input-dir data/val-sample/input --reference-dir data/val-sample/reference
uv run scripts/build.py solutions                       # -> dist/solution-*.zip
uv run scripts/build.py solutions --small               # -> dist/solution-*-small.zip
```

Pre-submission checklist: `coverage == 1.0`, `invalid_predictions == 0`,
deterministic across repeated runs, runs in the **competition Docker image** (not
just a local venv).
